# Classification Report — Quick Reference

**Classes:**

- 0 = Legitimate posting.
- 1 = Fraudulent posting.

**Precision:**

Of the postings predicted to belong to a class, how many actually belong to it?
For fraud: “How reliable are my fraud flags?”

**Recall:**

Of the postings that actually belong to a class, how many did the model correctly identify?
For fraud: “How much of the actual fraud did I catch?”

**F1-score:**

Combines precision and recall using their harmonic mean. It rewards having both high precision and high recall.

**Support:**

The actual number of examples belonging to each class in the evaluated dataset. It is not the number the model predicted.

**Accuracy:**

The fraction of all predictions that were correct, across both classes.

**Macro average:**

Calculates each metric separately for both classes, then takes their ordinary average. Both classes receive equal importance, regardless of their size.

**Weighted average:**

Averages each metric across classes, weighted by their support. Since legitimate postings are much more common here, they have more influence on this average.

**Reading the numbers:**

Precision, recall, F1, and accuracy range from 0 to 1; higher is better. For example, 0.87 means 87%. Support is a count.

**For this project:**

Pay particular attention to class 1 precision, recall, and F1. High accuracy or weighted averages can hide poor fraud detection.

## Why the warning appeared:

Changing zero_division would only change how this situation is reported; it would not improve the predictions.

## What I learned:

- Increasing alpha means stronger smoothing, but stronger smoothing does not necessarily improve the model.
- For this validation split, TF-IDF with alpha 1.0 performed worse than with alpha 0.1.
- The counts model performed better than TF-IDF when both used alpha 1.0.
- Approximately 96% accuracy is misleading here: predicting every posting as legitimate already achieves about 95.55% accuracy while catching no fraud.
- These results show the effect of the change, but do not establish the exact reason every fraud prediction disappeared.

## What the results mean:

- Approximately 94% of the TF-IDF model’s fraud flags were correct.
- It detected approximately 52% of actual fraudulent postings.
- It still missed approximately 48% of fraud.
- TF-IDF performed better than the counts model on all three fraud metrics.

## What I learned:

- This addresses exact-description overlap; it does not guarantee that all similar templates are separated.

## Current decision:
